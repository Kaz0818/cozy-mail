# 実装計画: Cozy Mail (Mac 版)

- 元になる仕様: [`SPEC.md`](../SPEC.md) (2026-11-12 承認)
- タスク一覧: [`tasks/todo.md`](todo.md)
- 状態: **下書き — オーナーの確認待ち**

## 概要

Gmail 3 アカウントと Yahoo!メールを 1 つの受信トレイで扱う Mac アプリを、次の 4 段階で作る。

1. **v0.0 見た目:** 仮のデータで、見本どおりの 3 列の画面とライト/ダークを作る。
2. **危険の確認:** 一番うまくいかない可能性が高い「IMAP の接続」と「Gmail の OAuth」を、画面より先に小さく試す。
3. **v0.1 実際に使える:** 本物のアカウントを追加して、読む・整理する・送るができる。
4. **v1.0 毎日使える:** 新着の即時通知、オフライン、下書き、送信取り消しなど。

v1.0 の部分 (フェーズ 4) は、v0.1 を使ってみてから細かく決め直す。いまは大まかな粒度にしてある。

## 設計の決定

| 決定 | 理由 |
|---|---|
| **画面は仮データの `MailRepository` 越しに作り、あとで本物に差し替える** | 見た目 (v0.0) を最初に確認できる。画面と同期処理を別々にテストできる |
| **画面より先に、IMAP と Gmail OAuth を小さなコマンドラインのツール (`cozymail-probe`) で試す** | 一番の危険は「`swift-nio-imap` が思ったより低レベルで手間がかかる」「Gmail が確認されていないアプリのログインを拒む」こと。早く分かれば、ライブラリや方式を変える判断が安くつく |
| **`Packages/` は Linux でもテストできるようにし、SwiftData とキーチェーンは Apple 専用のターゲットに分ける** | この作業環境 (クラウドの Linux) で、メール処理のテストを回せるようにするため。SwiftData とキーチェーンは Linux にない |
| **保存先は `MessageStore` プロトコルで隠し、テストはメモリ上の実装で行う** | 同期の動きを、SwiftData なしで速くテストできる |
| **アカウント追加は Yahoo! (アプリパスワード) を先、Gmail (OAuth) を後にする** | アプリパスワードの方が単純で、受信から表示までの流れを先に通せる |
| **Gmail の送信済みは Gmail に任せ、それ以外は SMTP 送信後に IMAP の `APPEND` で「送信済み」に入れる** | Gmail は SMTP で送ると自動で送信済みに入る。二重にしないため |

## 作業の流れと分担

この作業環境 (クラウドの Linux) では Xcode が動かない。そのため、確認を次のように分ける。

| 確認すること | どこで | 誰が |
|---|---|---|
| `Packages/` の単体テスト・結合テスト | この作業環境 (Swift の Linux 版を入れる) | Claude |
| アプリのビルドとテスト | GitHub Actions の macOS 26 (main への取り込み時と手動実行時だけ。PR では Linux のテストだけ) | Claude |
| 画面の見た目と操作 | オーナーの Mac (Xcode 26) | オーナー (手順は各タスクに書く) |
| 実際のアカウントでの送受信 | オーナーの Mac | オーナー |

画面を伴うタスクは、Claude が書いて PR にし、オーナーが Mac でビルドして確認する流れになる。

## 危険と対策

| 危険 | 影響 | 対策 |
|---|---|---|
| `swift-nio-imap` が低レベルで、思ったより作るものが多い | 大 | T7 で早めに試す。手間が大きすぎたら、別の IMAP ライブラリを使うか相談する (ライブラリの追加は「先に相談する」) |
| Google が、確認されていないアプリからの Gmail 全権限のログインを拒む | 大 | T9 で早めに試す。だめなら Gmail もアプリパスワードでつなぐ (SPEC の予備案) |
| この作業環境で Xcode が動かず、画面を Claude が確認できない | 中 | 画面のタスクには、オーナーが Mac で確認する手順を書く。メール処理は `Packages/` に寄せて、Linux でテストする |
| この作業環境に Swift の Linux 版を入れられない (ネットワークの制限など) | 中 | T1 で試す。だめなら、テストもオーナーの Mac で回す (GitHub Actions の macOS ランナーも候補。CI の追加は相談してから) |
| Liquid Glass の API (macOS 26) の細かい動きが資料と違う | 中 | T2 で小さく試す。見本との差はチェックポイント v0.0 で確認する |
| 日本語の古い文字コード (`ISO-2022-JP` など) の解析が難しい | 中 | T8 で、実際のメールを匿名化したサンプルを使ってテストする |
| Gmail で同じメールが複数のフォルダ (ラベル) に出て、二重に表示される | 中 | T10 で `X-GM-MSGID` を使って 1 通にまとめ、テストする |
