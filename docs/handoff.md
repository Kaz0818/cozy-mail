# 引き継ぎ書 — ローカル (Mac) とクラウドの作業の受け渡し

Cozy Mail は、2 つの場所で作業する。

| 場所 | 何ができるか | できないこと |
|---|---|---|
| **ローカル** (オーナーの Mac の Claude Code) | すべて。`swift test`、`xcodebuild test` (アプリ・UI テスト・SwiftData) | — |
| **クラウド** (claude.ai/code の Linux) | `Packages/` の `swift test`、コードを書く、PR、CI の macOS を手動で動かして結果を読む | SwiftData・アプリ・UI のテストを手元で動かす (CI の macOS 頼み) |

**作業を始める AI は、まずこのファイルを読む。作業を終える AI は、このファイルの「今の状況」と「作業の記録」を書き直してから終える。**

---

## 1. 受け渡しのやり方

### 始めるとき (ローカルでもクラウドでも同じ)
1. `git checkout main && git pull` で最新にする (クラウドは指定のブランチを main にそろえる)。
2. このファイルの「今の状況」と、[tasks/todo.md](../tasks/todo.md) の今のタスクを読む。
3. 作業用のブランチを作る (ローカル: 例 `swiftdata-store`。クラウド: 会話ごとに決められた `claude/...`)。

### 終えるとき
1. テストとビルドを通す ([CLAUDE.md](../CLAUDE.md) の「コマンド」)。
2. tasks/todo.md と tasks/plan.md のチェックを更新する (🍎 はオーナーが確認してから)。
3. **このファイルの「今の状況」と「作業の記録」を書き直す。** 次の人が最初に何をすればよいか分かるように。
4. コミット → プッシュ → 下書きの PR。オーナーがマージする。
5. マージされるまで、もう一方の場所では同じところを触らない。

### 守ること
- **ローカルとクラウドで、同時に同じブランチを触らない。** 受け渡しは、いつも main を通す (PR をマージしてから次へ)。
- まだマージしていない作業を、もう一方に渡したいときは、ブランチ名をこのファイルに書く。
- クラウドで SwiftData やアプリの画面のコードを変えたときは、CI の macOS を手動で動かして、結果を報告に書く。
